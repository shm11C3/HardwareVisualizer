# プロダクトアナリティクスとプライバシー

[English](product-analytics.md) | [日本語](product-analytics.ja.md)

このページは HardwareVisualizer のプロダクトアナリティクスに関する公開データ契約とプライバシー通知です。アプリ内の同意ダイアログと設定画面はこのページにリンクします。アナリティクスを送信できるリリースより前に公開しています。[現在の状態](#現在の状態) を参照してください。

## 現在の状態

**計画段階であり、まだどのリリースにも含まれていません。** 現時点でプロダクトアナリティクスを送信する HardwareVisualizer のリリースはありません。コードが出荷される前に決定を公開するため、意図的にこの通知を先に公開しています（[ADR 0028](../adr/0028-opt-in-product-analytics.md)）。opt-in を含む最初のバージョンはリリース時にここに記載します。また、この通知がマージされてから 30 日以内に安定版リリースに含めることはありません。

## プロダクトアナリティクスとは

稼働中のインストール数、ある月に新しく加わったインストールのうち後の月も稼働しているものの数、どの画面や機能が使われ、どれが無効のままか、どのハードウェアベンダー分類とセンサープロバイダーでアプリが動いているかを、メンテナーが把握するための集計値です。

クラッシュレポートでも診断情報でもなく、アプリ内での操作の記録でもありません。ハードウェアの読み値は一切含まれません。

## ユーザーの選択

- プロダクトアナリティクスは、新規インストールでもアップグレードでも **初期状態は無効** です。有効にするまで何も送信されません。
- 対象バージョンの初回起動時に、ダイアログが一度だけ確認します。「共有する」と「共有しない」は同じ重みで表示されます。選ばずにダイアログを閉じた場合は「共有しない」として扱います。
- **設定 → 詳細 → プロダクトアナリティクス** からいつでも有効・無効を切り替えられます。
- 無効にすると送信は直ちに停止し、送信待ちのデータは破棄され、後述するローカルの乱数シードは削除されます。後で再び有効にすると新しいシードが生成されるため、新しいインストールとして数えられます。
- 将来のバージョンがこのページに記載された以上の内容を送信しようとする場合、契約バージョンが上がり、新しい内容を送信する前にアプリが再度確認します。「共有しない」を選んだ場合は再度確認されません。

## 送信される内容（契約バージョン 1）

各バッチは小さな JSON ドキュメント 1 つで、プロジェクトが Cloudflare 上で運用するサービスへ HTTPS で送信されます。送信のタイミングは、起動から約 1 分後、その後アプリの稼働中は約 6 時間ごと、そしてアナリティクスを有効にした直後の 1 回です。

| フィールド | 例 | 目的 |
| --- | --- | --- |
| スキーマバージョンと同意バージョン | `1`, `1` | どの契約に従ったバッチかをサービスとこのページが正確に言えるようにするため |
| アプリバージョン | `1.12.0` | 新しいバージョンの普及状況 |
| OS ファミリー | `windows`, `macos`, `linux` | プラットフォーム別の内訳 |
| CPU アーキテクチャ | `x86_64`, `aarch64` | プラットフォーム別の内訳 |
| 同意した月 | `2026-11` | アナリティクスを有効にした月。その月のインストールのうち後の月も稼働しているものの数を算出するために使います |
| 日次トークンと月次トークン | それぞれ 16 進 32 文字 | インストールを UTC の 1 日に 1 回、1 か月に 1 回だけ数えるため。後述 |
| バッチ ID | ランダムな UUID | 応答が失われた場合に、受信済みのバッチをサービスが無視できるようにするため |
| Product Event カウンタ | `screen_view.performance: 12` | 各画面や機能が UTC の 1 日に何回使われたか |
| State Flag | `feature_on.tray_widget` | どの機能が有効か、どのレイアウトと表示が使われているか、CPU と GPU のベンダー分類、センサープロバイダーが利用可能だったか。UTC の 1 日に 1 回 |

### Product Event

- `screen_view.dashboard`, `screen_view.performance`, `screen_view.system_specifications`, `screen_view.usage`, `screen_view.cpu_detail`, `screen_view.insights`, `screen_view.settings`
- `capability.hardware_report_exported`, `capability.tray_widget_opened`, `capability.external_component_setup_started`
- `capability.insight_opened.hardware`, `.cooling`, `.gpu`, `.process`, `.snapshot`

カウンタは UTC の 1 日あたりの件数です。その日のいつ起きたかは含まれません。

### State Flag

true のフラグだけを、インストールごとに UTC の 1 日に最大 1 回送信します。

- `feature_on.hardware_archive`, `feature_on.storage_health`, `feature_on.tray_widget`, `feature_on.close_to_tray`, `feature_on.elevated_startup_mode`, `feature_on.ambient_sensor`, `feature_on.burn_in_shift`, `feature_on.background_image`
- `navigation.grouped`, `navigation.classic`
- `view.performance.panels`, `view.performance.compact`, `view.performance.monitor`
- `hardware.cpu_vendor.intel`, `.amd`, `.apple`, `.other`
- `hardware.gpu_vendor.nvidia`, `.amd`, `.intel`, `.apple`, `.other`（検出した GPU ベンダーごとに 1 つ）
- `provider_available.pawnio_cpu`, `provider_available.superio`

サービスは各フラグの日次合計を個別に保存します。1 つのインストールがどのフラグを同時に持っていたかは保存しないため、たとえば「アーカイブが無効で Tray Widget が有効なインストール」のような組み合わせは、このデータから分かりません。

## 送信されない内容

- 氏名、メールアドレス、ユーザー名、ホスト名、アカウント識別子。
- データの一部としての IP アドレス（通信自体には IP アドレスが伴います。[サービスでのデータの扱い](#サービスでのデータの扱い) を参照）。
- MAC アドレス、シリアル番号、デバイス ID、アプリがローカルに保存しているハードウェア識別情報。
- CPU、GPU、ストレージ、マザーボードなどのモデル名。
- プロセス名やアプリケーション名、ウィンドウタイトル、ファイルパス、ログ、スタックトレース、エラーメッセージ。
- ハードウェアの読み値：使用率、温度、消費電力、ファン回転数、健康状態、容量。
- 操作の正確なタイムスタンプ。
- ロケール、位置情報、国。

センサーチップの検証を手伝うなどの目的で、使っているハードウェアを正確にプロジェクトへ伝えたい場合は、ユーザー自身が投稿する別の手動の Hardware Compatibility Report があります（[#2500](https://github.com/shm11C3/HardwareVisualizer/issues/2500)）。

## インストールの数え方

アナリティクスを有効にすると、アプリは 32 バイトの乱数を生成して設定ファイルに保存します。このシードが PC の外へ出ることはありません。アプリはシードから UTC の日ごと、月ごとに異なるトークンを導出します。異なる日や月のトークン同士を結び付けることも、シードへ戻すこともできません。サービスは期間ごとに異なるトークンの数を数え、期間の終了から数日後にトークンの行を削除します。

恒久的なインストール識別子はありません。同意した月は、その月に opt-in したすべてのインストールが共有するグループのラベルです。これにより、個々のインストールを追跡することなく、月次合計から「11 月のインストールのうち 2 月に稼働していたのはいくつか」を算出できます。

## サービスでのデータの扱い

- サービスは別の公開リポジトリにある Cloudflare Worker と D1 データベースです。リポジトリへのリンクは最初のリリース前にこのページへ追加します。
- HTTPS リクエストは Cloudflare が配送します。その過程で Cloudflare は、送信元 IP アドレスを含む接続メタデータを Cloudflare 自身の規約のもとで処理します。アナリティクスのデータセットには IP アドレス、リクエストヘッダー、リクエスト本文は保存されず、サービスはそれらをログにも記録しません。エッジでのレート制限は接続に基づいて行われ、保存されたデータは使いません。
- ローテーションするトークンは、有効な日または月の間はオンライン識別子にあたります。したがってこの通知は「個人関連情報を一切処理しない」とは述べません。述べているのは、保存されるもののいずれもあなたを識別できず、期間をまたいでインストールを追跡できない、ということです。
- 保持期間：日次トークンの行はその日から 3 日後、月次トークンの行はその月から 3 日後に削除します。バッチ ID は重複排除のために 7 日間保持します。集計値（期間ごと、フラグごと、イベントごとの件数）は時系列として保持し、トークンは含みません。
- 公開される結果：プロジェクトの website には集計表のみを表示します。インストール数が 20 未満の内訳は表示しません。
- D1 の処理場所とサービスのソースはサービスリポジトリに記載し、リリース前にこのページから両方へリンクします。
