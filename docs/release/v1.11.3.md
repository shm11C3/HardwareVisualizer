# v1.11.3 Release Preparation

Prepare v1.11.3 on `1.11.x`, starting from the published `v1.11.2` tag
(`f2c539671123ff86c92812ae7199f80b88b7ae83`). This is a maintenance release
for existing installations. Keep DuckDB at 1.5.5 and exclude the new sensor
scopes, longer Insight periods, and navigation changes on develop.

## Draft Release Notes

- Update TLS dependencies to reject distrusted eMudhra/emSign certificate
  paths (CVE-2026-111943; RUSTSEC-2026-0381, 0382 and 0383).
- Update Rust dependencies for security and correctness, including rustls,
  event-listener, Tokio, quick-xml consumers and Windows component setup ZIP.
- Avoid a configuration-mode exit write associated with system hangs on
  certain secondary-slot ITE controllers. The affected-board mitigation has
  automated coverage; it has not been validated on the affected hardware.
- Correct native macOS window opacity when Transparent UI is disabled,
  reducing unnecessary composition work. Existing measurements are described
  in the [original evidence](../agents/lessons/macos-native-window-opacity.md);
  they are not a new v1.11.3 performance measurement.

## Release Gates

Local preparation on 2026-10-29 passed Core library tests (1,071 tests), Core
Clippy with all targets and warnings denied, frontend lint and production
build, Rust formatting, agent-guidance validation, and the release-evaluator
tests. Full App and frontend test completion is delegated to CI; the local
frontend run encountered a sandbox temporary-file `ENOENT` before its tests
could load. These local results do not replace the final supported-platform
CI runs or the native checks below.

- Run CI and CodeQL on the final `1.11.x` commit, including supported-platform
  builds, native E2E, license checks and Merge Gate. A passing source PR does
  not validate its backport.
- Re-scan the candidate dependency inventory and evaluate remaining findings
  against the release's actual consumers. The October 28 v1.11.2 scan is
  historical evidence, not a scan of this candidate.
- The candidate retains Zod 4.6.5 and includes a `v1.11.3` assessment based on
  its unchanged single-File schema. Synchronize that entry to the default
  branch's release evaluation policy before evaluating the published tag:
  the workflow reads policy from the default branch, not the release tag.
- Review residual `block-buffer` exposure and the zvariant-family maintenance
  notices. Do not claim all scanner findings are fixed.
- The ZIP advisory ignores expire on 2027-01-18 and match advisory IDs across
  versions. They also hide the DuckDB 1.5.5 build dependency's ZIP 6 findings;
  retaining that engine is an explicit build-dependency trade-off, not a fix.
  The updater's ZIP 4 exception relies on Windows-only extraction after update
  signature verification.
- Validate Windows component setup and signed update installation; inspect
  generated installer versions and third-party notices. Do not distribute
  unsigned CI artifacts as an official release.
- On macOS, check saved opacity at startup and runtime ON/OFF transitions,
  including transparent mode with blur zero. Windows tests cannot prove this.
- Do not provoke the known ITE hang on affected hardware. Preserve the pinned
  spec and the regression tests that prove the hazardous write is omitted.

The Tauri configuration is set to 1.11.3. The publish workflow derives its
release version from the tag and generates updater artifacts and platform
notices at build time. Creating `v1.11.3` starts publishing; branch preparation
must not create that tag until the release gates have been reviewed.
